# 서비스 규칙 작성 양식

이 양식은 판단 기준을 정리하기 위한 문서다. 빈칸을 AI가 임의의 전문가 관법으로 채우지 않는다. 패키지의 기본 후보만으로 충분하면 추가 규칙을 만들지 않아도 된다.

## 규칙의 역할

- ruleId와 버전:
- 답하려는 질문:
- 적용 domain과 kind:
- 대상 사람과 기간:
- 규칙의 성격: 관측 전달, 해석 후보, 결론 선택, 날짜 선택 중 해당 역할
- 출처: 실제 참고 문헌 또는 서비스 자체 정책 문서
- 검토 상태: implementation-policy, unreviewed, human-reviewed 중 실제 상태

## 필요한 재료

- 사용하는 공개 context 필드:
- 필요한 evidence 종류와 tags:
- 입력 시각의 정확도 등 조건:
- 필요한 보조 기간과 contextualEvidence:

## 결정 과정

1. 재료가 없을 때의 보류 기준:
2. 적용 조건:
3. 반대 조건과 결론에 미치는 영향:
4. 다른 규칙과 겹칠 때의 처리:
5. 최종 statement와 status:
6. supportingEvidenceIds와 counterEvidenceIds의 선택 조건:
7. caveats에 남길 해석 범위:

기간 질문은 해당 기간의 직접 근거를 포함한다. 일반 rating과 month-sequence를 직접 근거로 넣지 않는다. 보조 기간은 contextualEvidenceIds로 구분한다.

## 사례

| 사례 | 입력과 주요 근거 | 기대 결과 | 선택 이유 |
| --- | --- | --- | --- |
| 적용 | 작성 | 작성 | 작성 |
| 비적용 | 작성 | 작성 | 작성 |
| 반대 근거 | 작성 | 작성 | 작성 |
| 시각 미상 또는 재료 부족 | 작성 | 작성 | 작성 |
| 다른 기간의 근거 | 작성 | 거부 또는 현재 기간에서 제외 | 기간을 섞지 않음 |

## 문장과의 연결

어떤 의미를 LLM이 유지해야 하는지, 어떤 비유와 창작 장면을 허용하는지 적는다. 규칙 결과의 결론과 창작 장면은 각각 다른 데이터로 관리한다. 실제 사건의 발생 확률을 계산하지 않았다면 확률을 출력하지 않는다.
