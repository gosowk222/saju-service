# 출생지역 자료 (GeoNames)

출생지역 검색에 쓰는 한국 지역 목록을 어떻게 만드는지 정리한 문서다. 실행 중인 서비스는 GeoNames에 접속하지 않고, 이 과정으로 만든 파일만 읽는다. API 키는 필요 없다.

## 출처와 사용 조건

- 출처: [GeoNames](https://www.geonames.org/)
- 라이선스: [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). 출처를 표시하면 상업적 사용과 가공이 가능하다.
- 서비스의 출처 표시 위치: 출생지역 입력 화면과 마이 화면
- 자료는 있는 그대로 제공되며 정확성이 보장되지 않는다. 모든 국내 행정구역이 들어 있다고 가정하지 않는다.

## 다시 만드는 방법

```sh
npm run places:import              # 공식 자료를 내려받아 다시 만든다
npm run places:import -- --offline # data/geonames-raw 저장본으로 다시 만든다
```

결과 파일은 다음 두 개다.

| 파일 | 내용 |
| --- | --- |
| `src/data/places/kr-places.json` | 앱이 서버에서 검색하는 지역 목록과 자료 버전 |
| `src/data/places/kr-places.meta.json` | 원본 URL, 다운로드 날짜, 원본 해시, 항목 수, 재실행 명령 |

자료 버전은 원본 세 파일의 해시로 정해진다. 같은 원본이면 결과 파일이 바이트까지 같다. 다운로드 실패, 빈 파일, 검증 실패가 나면 기존 파일을 건드리지 않고 중단한다.

## 사용하는 원본

| 원본 | 용도 |
| --- | --- |
| `export/dump/KR.zip` | 기본 표 (좌표, 분류, 행정코드, 시간대) |
| `export/dump/alternatenames/KR.zip` | 언어 표시가 있는 한국어 이름 |
| `export/dump/admin1CodesASCII.txt` | 시·도 코드와 geonameId 연결 |

열 구조는 [공식 readme](https://download.geonames.org/export/dump/readme.txt), 분류 코드는 [공식 코드표](https://www.geonames.org/export/codes.html)를 기준으로 했다.

## 포함 기준

| 분류 코드 | 의미 | 처리 |
| --- | --- | --- |
| `PPLC` | 수도 | 포함 |
| `PPLA`, `PPLA2`, `PPLA3`, `PPLA4` | 행정구역 소재지 | 포함 |
| `ADM2` | 시·군·구 | 포함 |
| `ADM3` | 읍·면·동 | 포함 |
| `PPL` | 일반 거주지 | 인구 값이 있는 곳만 포함 |

## 제외 기준

- 산, 강, 하천, 저수지, 고개, 학교, 건물, 사찰, 공원 등 `P`, `A` 분류가 아닌 항목
- `PPL` 가운데 인구 값이 없는 곳. 약 5만 9천 건의 작은 마을로, 대부분 같은 이름이 겹치고 상위 구분이 어려워 검색 품질을 떨어뜨린다.
- `ADM1`(시·도). 도 전체의 중심점은 출생지로 부적절하다. 특별시·광역시는 `PPLC`, `PPLA` 행으로 들어온다.
- `ADM4`(리), `PPLX`(동네 구역), `PPLL`(소규모 거주지)
- 사라진 곳 (`PPLH`, `PPLQ`, `PPLW`)
- 한글 이름이 자료에 없는 항목. 이름을 임의로 만들지 않는다.

작은 마을에서 태어난 사용자는 그 지역의 읍·면이나 시·군을 고르면 된다. 경도 차이가 작아 계산 결과에 주는 영향도 작다.

## 한국어 이름 선택

1. 대체 이름 자료에서 언어가 `ko`이고, 옛 이름(`isHistoric`)이나 구어 표현(`isColloquial`)이 아닌 한글 이름만 후보로 삼는다.
2. 대표 이름(`isPreferredName`)을 먼저 쓴다. 행정구역은 시·군·구·읍·면·동 글자가 붙은 공식 이름을 우선한다.
3. 후보가 없으면 기본 표의 대체 이름 열에 있는 한글 이름을 쓴다.
4. 그래도 없으면 목록에서 뺀다.

별도 보정은 `scripts/import-geonames.ts`의 `NAME_OVERRIDES`에 geonameId와 근거를 함께 적고 메타 파일에 기록된다. 현재 보정 항목은 없다.

시·도 이름은 GeoNames 자료의 표기를 그대로 쓴다. 자료 시점에 따라 최근 명칭 변경(예: 강원특별자치도, 전북특별자치도)이 반영되지 않았을 수 있다.

## 중복 처리

상위 행정구역과 이름이 같으면 같은 곳으로 보고 한 건만 남긴다.

- 공식 이름이 있는 행정구역 행을 먼저 남기고, 진 행의 이름은 검색용 다른 이름으로 옮긴다.
- 비교할 때 시·군·구·읍·면 글자는 뺀다. 동(洞)은 다른 지역과 겹치기 쉬워서 빼지 않는다.
- 시·군 행과 그 안의 같은 이름 중심지는 같은 곳으로 본다.
- 좌표는 남긴 행의 값을 그대로 쓴다. 평균하거나 새로 만들지 않는다.

이름이 같아도 상위 행정구역이 다르면 다른 곳이다. 강원도 고성군과 경상남도 고성군은 따로 남기고 검색 결과에 상위 행정구역을 함께 보여 준다.

## 가져올 때 검사하는 항목

어느 하나라도 실패하면 결과를 쓰지 않는다.

- 결과가 1,500건 이상인지
- `countryCode`가 `KR`인지
- `geonameId`가 중복되지 않는지
- 위도·경도가 숫자이고 범위 안인지
- 위도 32.5~39, 경도 124~132 안인지 (뒤바뀐 값을 잡는다)
- 이름이 한글이고 상위 행정구역이 있는지
- 시간대가 유효한 IANA 값인지

## 표본 확인

대도시뿐 아니라 중소도시와 군 지역을 직접 검색해 확인했다. 서울, 부산, 세종, 제주, 강남구, 해운대구, 춘천, 안동, 남원, 김천, 고성(강원·경남 구분), 청송, 의성, 완도, 보은, 양평, 평창, 울릉, 단양, 강진, 왜관이 모두 검색된다. 같은 표본은 `tests/unit/places.test.ts`에서 자동으로 확인한다.

## 앱에서 쓰는 방식

- 브라우저에는 검색 결과 최대 20건만 내려보낸다. 원본 전체를 보내지 않는다.
- 브라우저는 고른 `geonameId`만 서버로 보낸다. 서버가 이 자료에서 다시 찾아 좌표와 시간대를 정한다.
- 엔진에는 `timezoneId`, `longitudeDeg`, `latitudeDeg`, `label`, `source`만 넘긴다.
- `sajuengine 0.1.0`에서 위도는 기록용이고 계산에 쓰이지 않는다. 계산에는 경도와 시간대만 쓰인다.
- 풀이를 만들 때의 지역 이름, 좌표, 시간대, 자료 버전을 풀이 기록에 함께 저장한다. 목록이 갱신되어도 기존 풀이는 바뀌지 않는다.
