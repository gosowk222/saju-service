# 무진 03. 입력과 개인화

> 이 문서는 사용자가 2026-11-12에 제공한 무진 상품 설계 명세 원문을 옮긴 것이다. 실제 코드와 다른 점과 구현 결정은 [00_START_HERE.md](00_START_HERE.md)에 기록한다.

## 1. 입력 흐름

상품 상세 첫 진입부터 상담 장면이 나온다.
캐릭터 안내와 하단 입력 UI로 진행한다.

순서:
1) 별명: 텍스트.
2) 성별: 남·여 선택, 현재 엔진 계약에 맞게 전달.
3) 생년월일: 기존 YYMMDD 입력 정책.
4) 출생시각: 시간 범위가 표시된 12지지 목록 + 시간 모름.
5) 출생지역: GeoNames 한국 도시 검색·선택.
6) 지금의 나: 선택적 상황 입력.
7) 진짜 궁금한 점: 선택적 텍스트.
8) 입력 확인과 수정.

생년월일:
- 기존 연도 변환 정책을 확인해 재사용한다.
- 변환된 전체 날짜를 확인 화면에 표시한다.
- 1901년/2001년을 추가로 고르는 팝업을 새로 만들지 않는다.
- 양력·음력·윤달은 기존 지원 정책과 엔진 계약을 유지한다.
- 앱에서 별도 달력 계산기를 만들지 않는다.

출생시각:
- 시간대 표시와 실제 엔진 입력 변환을 맞춘다.
- 시간 모름을 임의 시각으로 채우지 않는다.

출생지역:
- 기존 GeoNames 한국 도시 가공 데이터를 재사용한다.
- 없을 때만 기존 구축 정책에 따라 KR.zip 가공 절차를 만든다.
- 매 풀이마다 GeoNames API를 호출하지 않는다.
- 지역 ID·위도·경도·시간대 연결을 유지한다.
- 같은 도시명은 행정구역으로 구분한다.
- 출처와 필요한 표기를 유지한다.

## 2. 지금의 나

모두 선택 입력이다.
관계·가족은 펼쳐서 고르는 영역으로 둔다.
선택하지 않아도 10개 장을 모두 제공한다.

일·학업 상태: 최대 2개.
- 학생
- 취업 준비 중
- 직장에 다니는 중
- 프리랜서로 활동 중
- 사업을 운영하는 중
- 쉬거나 다음 활동을 준비하는 중
- 위 항목과 다른 상황

연결할 맥락:
- 학생: 학습·과제·팀 활동·진로 탐색.
- 취업 준비: 공고·지원 자료·포트폴리오·면접.
- 재직: 업무 범위·역할·평가·협업·보수 협의.
- 프리랜서: 견적·계약·수정·납품·정산.
- 사업: 고객·가격·제공 범위·비용·운영.
- 휴식·준비: 생활 일정·목표·활동 탐색.
- 기타: 특정 직업을 전제하지 않는 활동.

선택만으로 추정하지 않을 것:
- 학생의 나이·용돈.
- 취업 준비자의 무직·무소득.
- 직장인의 안정된 월급.
- 프리랜서의 수입 불안정·분쟁.
- 사업자의 직원·자금난.
- 쉬는 사람의 질병·번아웃.

두 상태를 고르면 선택 순서가 주업 순서라고 가정하지 않는다.
장과 질문에 더 맞는 맥락을 사용한다.

## 3. 관심 주제

문서 01의 10개 장 이름 그대로 제공한다.
최대 2개.
미선택은 골고루 보기다.

관심은 설명 비중만 바꾼다.
사주 점수·판단 강도를 바꾸지 않는다.
자유 질문의 답변 분야를 최대 2개로 제한하지 않는다.

## 4. 관계 상태

선택 1개, 기본 미응답.

- 현재 연애하지 않음
- 알아가는 사람이 있음
- 연애 중
- 결혼·동반생활 중
- 답하고 싶지 않음

연애하지 않는다고 연애를 원하는 것으로 가정하지 않는다.
결혼·동반생활이라고 자녀·공동재산·부양 의무를 만들지 않는다.
상대방의 속마음은 알 수 있는 사실로 취급하지 않는다.

## 5. 가족 관련 관심

질문:
가족 이야기에서 다루고 싶은 부분이 있나요?

- 가족의 기대와 내 선택
- 내 시간과 관계의 거리
- 독립이나 생활 변화
- 돌봄과 역할 분담
- 돈과 지원에 관한 이야기
- 특별히 다루고 싶은 내용 없음
- 답하고 싶지 않음

앞의 5개는 최대 2개.
마지막 2개는 다른 항목과 함께 선택하지 못하게 한다.

이것은 관심 주제다.
‘돌봄’ 선택을 아픈 가족·자녀의 존재로 바꾸지 않는다.
‘독립’ 선택을 실제 독립 예정·가족 불화로 바꾸지 않는다.

## 6. 자유 질문 처리

다음을 구분하고 출처를 보존한다.

- 본인의 현재 사실.
- 사용자가 직접 말한 과거 사실.
- 계획·희망.
- 가정.
- 타인에 대한 사용자의 관찰·우려.
- 실제로 답을 원하는 질문.
- 상품과 무관한 요청·명령.

“취업 준비 중인데 창업이 나을까요?”를 이미 사업하는 사실로 바꾸지 않는다.
“언제 취업하나요?”는 범위 안 질문이다.
취업일을 확정하지 않으면서 판단 가능한 활동 구간과 조건에 답한다.

종합 상품이므로 돈·연애·직업 등의 여러 질문을 각각 연결한다.
무관한 일반 요청은 최초 풀이에 반영하지 않는다.
사용자 입력이 시스템 지시·출력 형식·결제 권한을 바꾸지 못하게 한다.

기존 질문 분류 기능을 재사용한다.
무조건 새 분류 LLM 호출을 추가하지 않는다.
원문 저장과 생성용으로 정리한 범위 안 질문을 구분한다.

## 7. 설명 우선순위

실제 자유 질문 → 관심 주제 → 관련 상황 → 기본 설명.

사용자 사실과 충돌하는 장면은 제외한다.
사주를 이유로 사용자의 현실 설명을 부정하지 않는다.
상황별 완성 대본 여러 벌을 만들지 않는다.

다음 상태를 구분한다.
- 미응답.
- 비공개.
- 특별한 관심 없음.
- 응답 있음.

명확한 최근 퇴사처럼 시간 변화가 확인되면 최근 사실을 적용한다.
시간 구분 없이 충돌하면 충돌한 부분만 중립적으로 처리한다.
계획과 가정을 현재 사실로 승격하지 않는다.

생성 전 확인 화면에서 수정할 수 있게 한다.
생성 도중 새로운 필수 질문을 끼워 넣지 않는다.

## 8. 재사용

계산 재사용은 출생정보·엔진 설정·버전 기준.
풀이 재사용은 여기에 상품·규칙·상황·질문·페르소나·작성 버전을 포함한다.

입력이 바뀌면 관련 결과를 무효화하거나 새 revision으로 구분한다.
구매한 과거 풀이를 현재 프로필로 덮어쓰지 않는다.
