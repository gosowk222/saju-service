# 무진 06. 생성·저장·권한·사용량

> 이 문서는 사용자가 2026-11-12에 제공한 무진 상품 설계 명세 원문을 옮긴 것이다. 실제 코드와 다른 점과 구현 결정은 [00_START_HERE.md](00_START_HERE.md)에 기록한다.

## 1. 실제 코드 연결

현재 구조를 조사한다.

- 상품 정의: src/domain/products/first-overview.ts, types.ts.
- 분석 선택: src/server/engine/analyze.ts, features.ts.
- 작성 계획·표: src/domain/reading/plan.ts, chart.ts.
- 규칙: src/domain/rules/.
- 페르소나: src/domain/personas/index.ts와 연결 구조.
- 생성: src/server/llm/prompts.ts, narrate.ts.
- 기존 화면: src/components/messenger.tsx.
- 타이핑 지연: src/lib/typing-delay.ts.
- 사용량: generation_attempts, generation_usage와 관련 코드.

상품 설정만 추가하고 분석·규칙 경로가 여전히 묘묘에 고정된 상태를 남기지 않는다.
여러 판단 출처를 사용하는 장을 서비스 계획에서 표현한다.
긴 족자에 기존 말풍선별 타이핑 지연을 그대로 상속하지 않는다.

## 2. 생성 역할

계산·서비스 판단·개인화 재료 선택은 먼저 수행한다.

Pass 1:
- 충분한 설명이 있는 평문 초안.
- 결론·이유·조건·반대 근거·사용자 맥락·생활 적용·행동 제안.
- 무진 말투는 요구하지 않는다.
- 단순 판정 목록으로 끝내지 않는다.

Pass 2:
- 초안을 무진이 직접 설명하는 글로 재구성한다.
- 어미만 치환하지 않는다.
- 새 사주 판단을 만들지 않는다.
- 문서 04의 의미 보존 계약을 따른다.

무료와 유료에 각각 적용한다.
권한 전 유료 초안 생성은 금지한다.

## 3. 점진 처리

- Pass 1의 완성된 장 또는 의미 단위를 검증하고 저장한다.
- 해당 단위의 Pass 2를 실행 대기열에 넣는다.
- Pass 1 스트림 수신 루프에서 Pass 2 종료를 기다리지 않는다.
- 첫 표시 단위는 작게, 뒤쪽은 관련 장을 작은 묶음으로 처리할 수 있다.
- 동시 호출 수는 설정으로 제한한다.
- 임의 글자 수로 자르지 않는다.
- 결론과 조건이 함께 전달되도록 한다.

지원되는 구조화 스트림 방식으로 완성 단위를 추출한다.
전체 JSON을 정규식으로 억지 분리하지 않는다.
현재 API가 적합하지 않으면 작은 장 묶음별 요청으로 구현하고 이유를 기록한다.

2-pass는 역할 구분이지 항상 요청 2번이라는 뜻이 아니다.
분류·묶음·재시도 때문에 실제 호출 수는 달라질 수 있다.

공통 사실·핵심 판단·호칭·목차 요약은 공유한다.
이전 본문 전체를 매 요청에 계속 복사하지 않는다.
이미 사용한 장면 요약은 반복 감소에 활용하되 과도한 금칙어 목록으로 만들지 않는다.

사용자에게는 검증한 최종 결과만 보여준다.
평문 초안을 먼저 보여준 뒤 문체를 바꾸는 방식은 사용하지 않는다.

## 4. 데이터 계약

기존 타입과 저장 구조를 확장하며 같은 의미의 중복 테이블을 만들지 않는다.

필요 정보:
- 사용자·풀이·상품·페르소나 ID.
- 출생정보·상황·질문 스냅샷.
- 엔진·정책·규칙·프롬프트·모델·페르소나 버전.
- 기준일과 기간 ID.
- coverage와 한계.
- 질문별 채택 판단·근거·반대 조건.
- 사용자 사실과 출처.
- 장별 초안·최종문·상태.
- 생성 시도와 오류·사용량.

원국표·분포표의 값을 LLM이 다시 작성하거나 계산하지 않게 한다.
앱이 실제 데이터로 렌더링한다.

## 5. 검증과 재작성

최소 검증:
- 출력 스키마와 지원 블록.
- 존재하는 근거 ID와 대상·기간.
- 필수 질문·주제 누락.
- 날짜·수치·사용자 사실의 일치.
- 범위 밖 질문 재유입.
- 창작 장면의 사실화.
- 근거 없는 결과 확정.

참조 ID가 같다는 사실만으로 의미 보존을 증명했다고 하지 않는다.
대표 사례의 초안과 최종문을 사람이 비교할 수 있게 한다.

실패하면 실패 단위만 제한된 횟수로 재작성한다.
정상적인 직설성·유머까지 순화하지 않는다.
특정 어미·농담·캐릭터 단어 개수로 통과 여부를 판단하지 않는다.
기본적으로 제3의 LLM 심사를 모든 결과에 추가하지 않는다.

## 6. 저장과 재개

같은 readingId에 무료 결과·권한·유료 작업을 연결한다.

- Pass 1 완료 후 Pass 2 실패: 저장 초안으로 Pass 2만 재시도.
- 일부 장 완료 후 실패: 완료 장 보존.
- 새로고침: 상태와 완료 결과 복구.
- 재열람: 새 생성 없음.
- 입력 변경: revision이나 새 풀이로 구분.
- 늦게 도착한 이전 응답: 새 입력·작업을 덮어쓰지 않음.
- 과거 구매 결과: 당시 버전으로 유지.

유료 기간 기준일은 첫 유료 분석 시 Asia/Seoul로 고정한다.

HTTP 연결 종료 후에도 작업이 지속되는지는 실제 실행 환경을 확인한다.
근거 없이 백그라운드 지속 실행을 보장하지 않는다.
필요하면 기존 저장 상태로 재개하거나 최소한의 작업 실행 수단을 마련한다.
불필요한 외부 큐 서비스를 먼저 도입하지 않는다.

## 7. 이용권과 결제

기존 캠페인:
free-trial-2026-11

확인 당시 무료 이용권은 묘묘 전용이다.
새 요구에 맞게 같은 미사용 이용권으로 무진도 선택할 수 있게 확장한다.

- 서버 허용 상품과 실제 DB 소비 경로를 함께 수정한다.
- 묘묘 ID로 위장해서 무진을 이용하게 하지 않는다.
- 기존 발급·사용 이력을 보존한다.
- 이미 묘묘에 쓴 이용권을 되살리지 않는다.
- 새 상품 때문에 추가 자동 지급하지 않는다.
- 여러 탭에서 묘묘·무진을 동시에 선택해도 한 장을 이중 소비하지 못하게 한다.

운영 게이트:
- readings_open_to_all.
- requireReadingAccess.
- 기존 사용자·관리자 정책.

결제 모드:
- CHECKOUT_MODE의 현재 설정 유지.
- free_trial에서는 이용권 흐름만 제공.
- payment에서만 기존 테스트 결제 연결.
- PAYMENTS_ALLOW_LIVE 제한 유지.
- 실결제와 전체 공개를 임의로 활성화하지 않는다.

결제·이용권·중복 통지·재시도는 기존 원자적 처리와 고유 제약을 활용한다.
생성 재시도 때문에 재결제하거나 이용권을 다시 소비하지 않는다.

## 8. 접근 제어

모든 개인 결과 요청은 소유권을 확인한다.
유료 본문과 관련 기능은 구매·이용권 권한을 추가 확인한다.
무료 맛보기 읽기에 구매를 요구하지 않는다.

조회·재개·다운로드·후속질문에서 동일하게 적용한다.
클라이언트의 paid, amount, 사용자 수정 가능한 프로필 값을 신뢰하지 않는다.

기존 Supabase 인증·RLS·서버 함수 구조를 따른다.
뷰가 소유권을 우회하지 않는지 확인한다.
필요한 DB 변경은 새 migration으로 남긴다.
기존 데이터 삭제나 프로덕션 임의 적용은 하지 않는다.

## 9. 토큰과 시간

기존 generation_attempts와 generation_usage 구조를 확인해 확장한다.
후속질문 usage도 기존 방식과 연결한다.

각 실제 호출 시도에 기록:
- 풀이 ID.
- 단계: 무료/유료, Pass 1/2, 분류, 후속질문.
- 장 또는 묶음 ID.
- 모델·프롬프트 버전.
- 공급자 요청/시도 식별자.
- 상태·시작·종료 시각.
- 입력 토큰.
- 출력 토큰.
- 캐시 입력 토큰.
- 사용량 수신 완료 여부.

실패·재작성 호출도 공급자 사용량이 제공되면 보존한다.
재시도가 이전 시도 기록을 덮어쓰지 않게 한다.

캐시 입력 토큰은 입력 토큰의 부분집합이다.
입력+출력+캐시로 중복 합산하지 않는다.
미수신 값을 0으로 채우거나 글자 수로 추정하지 않는다.
미확인은 null 등 기존 계약에 맞춰 구분한다.

관리 권한이 있는 기존 운영 화면에서 단계별·전체 사용량을 볼 수 있게 연결한다.
사용자 원문과 생성 원문을 공개 로그에 복제하지 않는다.

시간 측정:
- 무료 첫 유의미한 내용 표시.
- 권한 획득 후 첫 유료 내용 표시.
- 전체 모델 생성 완료.
- 실제 화면 표시 완료.

인사나 애니메이션 표시 시간을 풀이 생성 시간으로 포장하지 않는다.
Mock으로 실제 속도·비용 개선을 주장하지 않는다.

## 10. 모델과 환경 변수

현재 모델 설정과 LLM 클라이언트를 재사용한다.
이 작업에서 모델 ID나 추론 강도를 임의로 바꾸지 않는다.
존재를 확인하지 않은 모델 이름을 새로 넣지 않는다.

추가 환경 변수가 필요하면:
이름 / 목적 / 필수 여부 / 기본값 / 서버 전용 여부를 기록한다.

실제 키 값을 읽거나 출력하지 않는다.
새 키가 필요 없으면 기존 키로 충분하다고 보고한다.
필요한 예시는 .env.example에 비밀값 없이 기록한다.
