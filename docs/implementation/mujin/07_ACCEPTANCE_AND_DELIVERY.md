# 무진 07. 검증과 완료 기준

> 이 문서는 사용자가 2026-11-12에 제공한 무진 상품 설계 명세 원문을 옮긴 것이다. 실제 코드와 다른 점과 구현 결정은 [00_START_HERE.md](00_START_HERE.md)에 기록한다.

## 1. 구현 순서

- 기존 코드와 정책 조사.
- 요구사항과 실제 코드 연결표 작성.
- 추가 리소스 현황 보고.
- 상품별 분석·규칙·입력·페르소나 연결.
- 무료·유료 2-pass와 저장·사용량·권한 구현.
- 대화형 입력·장면·족자·부분 실패·재개 구현.
- 보관함·후속질문·PDF 연결.
- 테스트와 관련 문서 갱신.

단계별 승인 대기로 끝내지 않는다.
리소스 부족은 기능 개발과 분리해 관리한다.

## 2. 판단·개인화 검증

다음을 포함한다.

- 같은 원국에 다른 상황: 계산·기본 판단 유지, 설명 맥락 변화.
- 같은 상황에 다른 판단: 직업명만 바꾼 같은 대본 방지.
- 시각 미상과 임계값 근처: 보류·coverage 유지.
- 단순 오행 개수와 가중 비율 구분.
- 원국 12운성과 다른 기간 항목 분리.
- 신규 의미 태그가 실제 채택 판단에서만 나오는지.
- 가족 미응답·비공개·돌봄 관심에서 가족사 발명 방지.
- 두 직업 상태의 중복·모순 방지.
- 계획·가정과 현재 사실 구분.
- 여러 자유 질문의 누락 방지.
- 무관한 요청과 프롬프트 명령 유입 방지.
- 강약→체력·경제적 감당력 연결 제외.
- 동일 원인 중복 집계 방지.
- 혼합·중립·자료 부족 구분.
- 실제 대운·세운·절기 월 경계와 기준일 고정.

## 3. 생성·구매 검증

- 무료 성향까지 완결되는지.
- 권한 전 유료 초안 호출·저장·응답 유출이 없는지.
- 다른 사용자 결과 조회·재개·PDF·후속질문 차단.
- 미사용 이용권의 무진 사용.
- 이미 사용한 이용권의 재사용 차단.
- 여러 탭·중복 통지·연속 클릭의 이중 소비·중복 작업 방지.
- 기존 관리자 게이트 유지.
- free_trial과 payment 분리.
- Pass 2가 Pass 1 스트림 수신을 막지 않는지.
- 장 순서가 뒤집혀 완료돼도 화면 순서 유지.
- 실패 단계만 재시도.
- 연결 종료·새로고침·작업 재개.
- 이전 작업 응답이 새 상태를 덮어쓰지 않는지.
- 재열람에서 생성과 차감이 발생하지 않는지.
- 입력·출력·캐시 사용량과 미확인 상태 기록.
- 기존 묘묘 결과와 진행 중 작업의 회귀 방지.

## 4. 무진 품질 평가

평가할 것:
- 일반적인 존댓말 해설과 무진이 구별되는가.
- 첫 인사뿐 아니라 중간의 긴 장에도 성격이 남는가.
- 무엇을 먼저 짚고 어떤 차이를 설명하는지에 관찰력이 있는가.
- 약점의 조건과 손해, 조정 방향이 선명한가.
- 핵심 답과 설명의 깊이가 줄지 않았는가.
- 차·향·농담·반문이 반복되지 않는가.
- 무거운 고민에서도 고통을 희화화하지 않으면서 무진의 태도가 남는가.
- 새 사용자 사실이나 판단이 추가되지 않았는가.
- Pass 1의 조건·날짜·수치·행동 제안이 유지되는가.

대표 평가 입력:
- 상황과 질문 미응답.
- 두 활동을 병행하며 일·돈을 함께 질문.
- 준비가 길어지는 판단과 실행이 앞서는 판단.
- 연애하지 않지만 연애 희망을 밝히지 않은 경우.
- 가족·생활 고민이 있으나 구성원·증상을 밝히지 않은 경우.
- 시각 미상과 보류.
- 결과 확정을 강하게 요구하는 질문.
- 실제로 무거운 상황을 밝힌 경우.

자동 코드 테스트만으로 문체 품질 검증 완료라고 하지 않는다.
초안과 최종문을 나란히 비교할 수 있는 자료를 준비한다.
실제 모델 평가는 현재 정책대로 사용자가 실행한다.

## 5. 화면 검증

- 모바일·데스크톱 입력과 뒤로 가기.
- 한글 조합·키보드·안전 영역.
- 실제 계산과 생성 상태 구분.
- 읽기 쉬운 족자 문단·표·목차.
- 새 장 등장 시 읽는 위치 유지.
- 잠금·작성 중·오류·완료 구분.
- 영상 실패와 reduced-motion.
- 키보드·스크린리더.
- PDF의 표·장 제목·페이지 경계.
- 보관함에서 상품별 화면 연결.

## 6. 검사 명령

현재 package.json과 규칙을 먼저 확인한다.

기준 코드에서 확인된 명령:
- npm run typecheck
- npm run lint
- npm test
- npm run test:db-concurrency
- npm run test:e2e:clean

동시성 검사는 로컬 Postgres로 수행한다.
원격 Supabase DB를 테스트용으로 사용하지 않는다.
실제 환경 파일에서 테스트 주소를 읽지 않는다.

빌드는 환경 파일을 제외하는 test:e2e:clean 경로에서 확인한다.
직접 dev/build/start로 실제 환경 파일을 자동 로드하지 않는다.

가짜 인증·결제·고정 풀이는 기존 테스트 전용 gateway에서만 사용한다.
운영 앱 코드에 가짜 성공 경로를 넣지 않는다.

실제 모델 비교는 기존 llm:export와 llm:render의 모델 비호출 경로를 확인해 확장한다.
사용자가 직접 실행하고 결과를 비교할 수 있는 절차를 제공한다.
에이전트가 llm:compare, llm:check나 실제 키가 연결된 앱으로 우회 호출하지 않는다.

실제 모델 미실행은 LIVE_NOT_RUN.
실제 OAuth·결제 미검증도 별도로 명시한다.

## 7. 문서 갱신

실제 구현에 맞춰 다음을 갱신한다.

- 상품·페르소나 설명.
- 규칙과 미감수 상태.
- 상황 입력 계약.
- 2-pass와 저장·재개.
- 이용권의 대상 상품.
- 토큰 기록·조회.
- 리소스 현황.
- 테스트와 사용자 실행 방법.
- 필요한 AGENTS.md·CLAUDE.md 연결.

무진의 존댓말·족자·과거 사건 비창작 정책은 새 상품에 적용한다.
묘묘의 기존 계약을 전역으로 덮어쓰지 않는다.
실제 API 호출·환경 파일·보안 제한을 삭제하지 않는다.

## 8. 최종 보고

쉬운 한국어로 다음을 보고한다.

- 실제 구현된 사용자 흐름.
- 기존 코드 재사용과 신규 규칙.
- 2-pass 호출 단위와 저장·재개 방식.
- 실행한 검사와 결과.
- LIVE_NOT_RUN 및 실제로 검증하지 못한 항목.
- 제공 이미지의 사용 위치.
- 코드로 만든 연출.
- 임시 리소스와 추가 제작이 필요한 리소스의 정확한 규격.
- 새 환경 변수와 키 필요 여부.
- DB migration과 적용 상태.
- 가격 등 미확정 운영값.
- 고전 요약·궁통보감 자료 사용 여부와 이유.
- 실제 시간·토큰을 측정했는지 여부.
- 브랜치와 사용자가 받아서 확인하는 방법.

기능 완료와 최종 아트 완료를 구분한다.
임시 이미지로 작동하는 것을 최종 애니메이션 완료라고 보고하지 않는다.
반대로 최종 이미지가 없다는 이유로 독립적인 기능 구현을 남겨두지 않는다.
