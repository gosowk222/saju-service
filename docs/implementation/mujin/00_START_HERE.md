## 3. 구현 범위

이번 작업에 포함한 것.

- 무진 상품 정의와 무진 도사 페르소나(단일 원천 등록)
- 45개 질문(P01~P05, 1-1~10-4)을 기존 규칙·엔진 계산에 연결하는 무진 작성 계획
- 대화형 입력(지금의 나, 진짜 궁금한 점 포함)과 입력 확인
- 무료(원국표, 기초 분석 4개, 1장)와 유료(2~10장, 마지막 정리)의 장 단위 2-pass 생성, 저장, 재개, 부분 재시도
- 족자 보고서 화면, 상담 장면(임시 정지 그림), 목차와 현재 위치
- 무료 이용권의 무진 사용, 결제 모드 연결(기존 테스트 결제 경로)
- 보관함·후속 질문·PDF 연결
- 호출 단위 토큰 기록과 관리자 화면 조회
- 테스트(단위, PGlite DB, 가짜 서버 브라우저 테스트), 모델 비교 스크립트(`llm:export`·`llm:render`) 확장, 문서

포함하지 않은 것: 실결제 활성화, 전체 공개 전환, 프로덕션 배포·운영 DB 적용, main/develop 병합, 실제 모델 평가(사용자가 직접 실행), 최종 아트·영상 제작.

## 5. 결정 사항

1. 식별자: 상품 `mujin-overview`, 페르소나 `mujin`, 캐릭터 이름 '무진 도사', 상품 이름 '무진의 종합 사주'.
2. 상품 형식: 상품 정의의 `format`. 묘묘는 메신저(기존 정의 내용 변경 없음), 무진은 족자(`scroll`).
3. 가격: 서버 상품 설정의 `priceKrw`에 990원을 **임시값**으로 둔다(`priceStatus: "provisional"`, 화면에 '출시 전 임시 가격'). 기존 테스트 가격과 같은 값을 결제 모드 테스트용으로 쓴 것이며 출시 가격이 아니다.
4. 결제 전 LLM: 묘묘는 지금처럼 결제 전 LLM 호출이 없다. 무진은 무료 범위(기초 분석·1장)를 결제 전에 2-pass로 만든다. 유료 장의 초안·완성문은 권한 확인 뒤에만 만들고, DB 저장 함수가 권한을 다시 확인한다.
5. 무료 생성 비용 상한: 풀이당 무료 단계 시작 8회, 회원당 24시간 새 무료 단계 10개(구매 권한이 있는 풀이는 세지 않음), 장마다 Pass 1·Pass 2 각 3회. 값은 임시값이다(미확정 7).
6. 저장: 유료 단계는 기존 `generation_jobs`(권한, 이용권 완료, 점유)를 그대로 쓴다. 무료 단계는 `generation_jobs`를 쓰면 이용권 사용·결제가 막히므로 `reading_free_runs`로 점유한다. Pass 1 초안은 브라우저가 읽을 수 없는 `reading_units`에만 둔다.
7. 2-pass 호출 단위: 10절 참고.
8. 입력 순서: 출생지역을 출생시각보다 먼저 받는다. 시진의 실제 시계 범위가 지역의 시간대·경도로 계산되기 때문이다(명세 순서와 다름). 시각 목록은 엔진 계약대로 자시를 새벽·밤으로 나눈 13개와 '시간 모름'이다.
9. 기준일: 첫 유료 생성이 시작될 때 Asia/Seoul 날짜를 `generation_jobs.reference_date`에 고정하고 재시도·재열람·후속 질문에서 그대로 쓴다.
10. 9장: 출생 시각을 모르면 엔진이 대운을 계산하지 않는다. 이 경우 9장은 근거 부족으로 설명하고 대운을 임의로 고르지 않는다.
11. 규칙: 기존 `first-overview.*` 규칙 결론을 재사용하되, 명세가 제외한 연결(강약→체력·회복·수입 변동, 가족사 짐작, 용신으로 사람 판정, 주변 평가 단정)은 무진 계획에서 빼거나 무진용 중립 문장으로 바꾼다. 새 연결과 태그표는 `mujin-overview` 1.0.0이고 모두 `unreviewed`다. 새 `InquiryRule`은 등록하지 않았다.
12. 고전 요약·궁통보감: 쓰지 않았다. 요약은 AI 작성·자동검사 상태이고(사람 감수 0건), 궁통보감은 일간·월지 조건만 맞추는 처방이라 이미 채택한 판단을 설명하는 데 필요하지 않다. 사용하려면 장별로 채택 판단과 맞는 자료만 고르는 별도 작업이 필요하다.
13. 모델·추론 강도: 기존 설정을 재사용한다(모델 `OPENAI_MODEL`, Pass 1·Pass 2는 최초 풀이와 같은 medium, 질문 정리·후속 질문은 기존 low). 새 환경 변수와 새 키는 필요 없다.
14. 상담 장면: B01~B04가 없으므로 캐릭터 설정화의 얼굴 크롭과 정지 장면 + 상태 문구로 임시 구현했다. 임시 리소스이며 최종 아트 완료가 아니다.
15. 그림 속 글자: 무진 배너·포스터에는 글자가 이미 있으므로 화면 글자를 그림 위에 겹치지 않고, 화면 읽기용 제목과 상품 정보는 따로 둔다. 배너는 원본 비율로 보인다.
16. 이용권: 대상 상품에 무진을 더했다. 캠페인 ID는 그대로라 추가 지급이 없고, 한 장은 두 상품 중 하나에만 쓰인다(기존 회원 단위 잠금).
17. PDF: 묘묘와 같이 권한이 있고 유료 단계까지 끝난 풀이만 내보낸다.
18. 유료 시작 조건: 무료 단계가 끝난 뒤 시작한다. 무료 단계가 더 다시 시도할 수 없는 실패로 끝났으면 구매한 유료 장은 시작한다.
19. 상품 상세: 배너 아래에 상담 장면과 무진의 첫 인사를 두고, '무진과 상담 시작하기'로 대화형 입력(로그인 필요)으로 이어진다.
20. 문답 예시 (2026-11-13 정책 변경, 명세 04 7절을 바꿈): 사용자가 준 원문 21개를 받은 그대로 카탈로그(`src/domain/personas/examples/`)에 두고, 원문 05·07·09·10을 참조하는 Pass 2 재작성 예시 4개를 더했다. 묶음 `mujin-1.1.0`부터 Pass 2는 장마다 재작성 예시 하나와 문답 하나, 후속 답변은 질문·반응에 맞는 문답 두세 개를 지시 끝에 넣는다. Pass 1과 질문 정리에는 넣지 않는다. 1.0.0 묶음에 고정된 단계는 예시 없이 이어 쓴다. 설명은 `docs/personas/examples.md`.

## 6. 미확정 사항

1. 출시 가격 (현재 임시 990원).
2. 상담 장면 최종 아트(B01~B04)와 프로필 그림(B05).
3. 실제 모델로 본 무진 문체 품질과 질문 정리 정확도 (사용자 실행, LIVE_NOT_RUN).
4. 문답 예시를 넣은 Pass 2·후속 답변의 실제 모델 효과 (예시 사용 mujin-1.1.0과 미사용 mujin-1.0.0 비교, 사용자 실행, LIVE_NOT_RUN). 21개 원문은 2026-11-13에 받아 넣었다 (결정 20).
5. 무진만 따로 공개·비공개하는 운영 설정 (현재 공개 설정은 모든 상품 공통).
6. 고전 자료 사용 여부.
7. 무료 생성 비용 상한 값(시작 8회, 하루 10개, 장별 3회)과 실제 지연에서 요청 하나(270초)에 들어가는 묶음 수.
8. 디자인 토큰 확장(종이 면 색, 중간 크기 serif 제목, 바텀시트 배경, z-index 단계 — `docs/DESIGN_NOTES.md`).
9. 실제 카카오 로그인·결제·로컬 Postgres 동시성 검증 (NOT_RUN).
10. 무진 판단 연결·태그·중립 문장·12운성 뜻의 명리 감수 (모두 unreviewed).

## 10. 구현 요약

### 사용자 흐름

상품 상세(배너, 상담 장면, 장 목록, 임시 가격) → '무진과 상담 시작하기' → 카카오 로그인 → 대화형 입력(별명, 성별, 생년월일, 출생지역, 출생시각, 지금의 나, 진짜 궁금한 점, 확인·수정) → 풀이 기록 생성(원국 계산과 작성 계획 저장) → 족자 화면에서 무료 단계 자동 시작(원국표, 기초 분석 4개, 1장) → 잠긴 유료 장 아래 이용권(무료 테스트 모드) 또는 결제(결제 모드) → 같은 화면에서 유료 장이 완성되는 대로 표시(목차 순서 유지, 자동 스크롤 없음) → 전체 완료 뒤 후속 질문 패널과 PDF → 보관함에서 다시 열기(재생성·재차감 없음).

### 2-pass 호출 단위

| 단계 | Pass 1 (평문 초안, 스트림) | Pass 2 (무진 문장) |
| --- | --- | --- |
| 무료 | `free-basics`(기초 분석 4개) 1회, `free-ch1` 1회 | 장마다 1회(5회), 동시 2개 |
| 유료 | `paid-work`(2·3장), `paid-money-love`(4·5장), `paid-people-life`(6·7·8장), `paid-flow`(9·10장), `paid-closing`(마지막 정리, 다른 장 초안의 핵심 답을 받은 뒤) 각 1회 | 장마다 1회(10회), 동시 2개 |

- 질문 정리(궁금한 점이 있을 때만)는 무료 단계에서 1회 부르고 저장해 다시 쓴다.
- Pass 1 스트림에서 장 원소가 닫힐 때마다 검사하고 초안을 저장한 뒤 Pass 2 대기열에 넣는다. 수신 루프는 Pass 2를 기다리지 않는다.
- 검사에 걸린 장만 같은 요청에서 1회 다시 요청하고, 장마다 Pass 1·Pass 2 시도 총수 3회까지. 호출 수는 재시도에 따라 달라진다(2-pass는 역할 구분이지 항상 2회가 아니다).
- 버전은 묶음으로 단계마다 작업에 고정한다. 현재 `mujin-1.1.0`(mujin-draft-1.0.0, mujin-voice-1.1.0, mujin-question-1.0.0, mujin-followup-1.1.0, 무진 1.0.0, guide-1.0.0, 문답 예시 카탈로그 mujin-examples-1.0.0·선택 정책 example-select-1.0.0). 그 전 `mujin-1.0.0`(voice·followup 1.0.0, 예시 없음)에 고정된 단계는 그대로 이어 쓴다.

### 저장과 재개

- 요청 하나는 270초 예산 안에서 쓸 수 있는 만큼 쓰고, 남은 장이 있으면 점유를 반납(partial)해 화면이 곧바로 다시 요청한다. 점유 300초, 무료 시작 8회·유료 시작 20회 상한.
- 전역 동시 호출 자리를 기다린 뒤 남은 시간이 부족하면 보내지 않고 반납한다(장 시도 수로 세지 않음).
- 초안까지 저장된 장은 Pass 2만 다시 하고, 완성된 장은 다시 만들지 않는다. 점유를 잃은 요청은 저장하지 않는다(DB가 시도 번호·점유 시간·권한을 다시 확인).
- 단계 전체가 실패하면 끝나지 않은 장을 오류로 보이고 다시 시도할 수 있다. 유료 전체가 끝나면 `complete_generation`이 작업과 이용권을 한 트랜잭션으로 완료한다.
- 서버 응답 뒤에 작업이 계속된다고 가정하지 않는다. 진행 중이던 요청은 끝까지 쓰고, 그 뒤에는 화면을 다시 열면 저장된 장부터 이어 쓴다.

### 토큰과 시간 기록

- 실제 HTTP 호출 시도마다 `llm_calls`에 한 줄(단계 free/paid, 종류 classify/pass1/pass2/followup, 장·묶음 ID, 모델·프롬프트·스키마·페르소나 버전, 응답·요청 ID, 시작·끝, 입력·출력·캐시 입력·추론 토큰, 사용량 수신 여부). 받지 못한 값은 null, 캐시 입력은 입력에 포함된 값이라 더하지 않는다.
- 관리자 화면(`/admin`)에서 풀이별·단계별 합계와 DB 시각으로 계산한 생성 시간(무료 첫 장, 무료 완료, 권한 뒤 첫 유료 장, 권한 뒤 전체 완료)을 본다. '화면에 실제로 보인 시각'은 서버가 알 수 없어 없다.
- 실제 모델 호출이 없어서 실제 시간·토큰은 측정하지 않았다.

### migration
