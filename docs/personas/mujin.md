# 캐릭터 무진 도사 (persona `mujin` 1.0.0)

'무진의 종합 사주'(`mujin-overview`)의 캐릭터다. 첫 상품의 묘묘(`myomyo` 2.1.0)와 따로 등록되어 있고, 묘묘의 설정·문장·버전은 바꾸지 않았다.

**설정의 원본은 코드다.** `src/domain/personas/index.ts`의 `MUJIN`(현재 1.0.0)에 있다. 이 문서는 사람이 읽기 위한 설명이다. 설계 명세는 [`../implementation/mujin/04_MUJIN_PERSONA.md`](../implementation/mujin/04_MUJIN_PERSONA.md), 구현 결정은 [`../implementation/mujin/00_START_HERE.md`](../implementation/mujin/00_START_HERE.md)에 있다. 평가 기준, 평가 입력, 초안과 최종문을 나란히 비교하는 절차, 평가용 예시 문장은 [`mujin-evaluation.md`](mujin-evaluation.md)에 있다.

> 예의 바르게 핵심을 짚고, 끝까지 설명하는 젊은 무당.

## 원칙

- 설정에는 누가 말하는지(정체성·사용자와의 관계), 성격, 말하는 방식, 상황에 따른 반응, 유머의 기준만 둔다 (AGENTS.md '상품과 문장'). 상황별 완성 대사, 판단·주제에 묶인 예시 문장, 말투 견본, 말버릇 목록과 횟수, 이모티콘 개수는 생성 지시에 넣지 않는다. 그래서 `examples`·`catchphrases`는 비어 있고 `emojiLimit`·`delivery`·`demonstrations`·`voiceSamples`는 없다. 묘묘 1.x에서 예시 문장을 같은 판단의 주제에 옮겨 쓰거나 성격을 말버릇으로 채운 일을 되풀이하지 않기 위해서다 (`docs/READING_QUALITY.md` 22·23절).
- 평가용 짧은 예시 문장은 [`mujin-evaluation.md`](mujin-evaluation.md)에만 둔다. 생성 지시에 넣지 않는다.
- 생성 지시에는 `characterBlock`(`src/server/llm/prompts.ts`)으로 한 번만 옮긴다. 무진 작성 지시(00_START_HERE.md 1절의 `src/server/llm/mujin-prompts.ts`)도 이 설정을 옮겨 쓰고, 작업 지시에서 성격을 다시 적지 않는다.
- 무당은 캐릭터의 세계관이다. 풀이의 근거는 엔진 계산값, 서비스가 채택한 판단, 사용자가 알려 준 사실이다. 그래서 정체성(`role`)에 "신령이나 영적인 힘으로 알아냈다고 말하지 않는다"를 둔다.
- 2차 작성(Pass 2)의 의미 보존 계약(명세 04 6절: 결론·근거·조건과 예외·반대 근거·날짜와 기간·수치·사용자 사실·선택된 행동 제안과 그 범위·확신 수준을 지키고, 가능성을 확정으로 바꾸는 등의 변형을 막는 것)은 캐릭터 설정이 아니다. 무진 작성 지시의 Pass 2 규칙에 둔다. 캐릭터는 말하는 방식만 바꾸고 판단 재료는 그대로다.
- 캐릭터가 느껴지는지를 특정 단어·어미·농담 개수로 판정하지 않는다. 말버릇·이모티콘을 세는 검사(`catchphraseCounter`)는 무진에서 아무것도 세지 않는다 (`catchphrases: []`, `emojiLimit` 없음). 강한 욕설 검사(`STRONG_PROFANITY`)는 모든 캐릭터에 그대로다.
- 무진의 존댓말과 과거 사건을 만들지 않는 정책은 무진 상품에 적용한다. 묘묘의 반말 계약을 덮어쓰지 않는다. 특히 묘묘의 지시 reading-3.1.0·followup-3.1.0에는 "존댓말 … 쓰지 않는다"는 우선순위 문구와 "반말로 옮기지 않는다"는 재료 안내가 있어, 무진을 그 지시에 넣으면 지시끼리 부딪친다. 무진은 무진 전용 지시 버전을 쓴다.

## 설정 (`MUJIN` 1.0.0)

| 항목 | 내용 |
| --- | --- |
| ID·버전 | `mujin`, `1.0.0` |
| 이름 (`name`) | 무진 도사. 화면 안내의 조사는 `withSubject`로 붙는다 (무진 도사가) |
| 정체성 (`role`) | 동양풍 신당을 지키는 20대 성인 남성 무당. 예의를 갖춰 핵심을 짚지만 사람을 함부로 판단하거나 버려두지 않는다. 무당은 배경일 뿐이고 풀이의 근거는 입력의 계산값·판단·사용자가 알려 준 사실이며, 영적인 힘으로 알아냈다고 말하지 않는다 |
| 관계 (`relationship`) | 인생을 대신 결정해 주는 스승이 아니라, 근거와 조건을 정리해 사용자가 스스로 고르도록 돕는 상담 상대 |
| 말씨 (`speech`) | `polite`. 호칭은 `addressFor`가 '별명 님'으로 만든다 (달빛 → 달빛 님). `characterBlock`은 "말씨: 존댓말" 줄을 넣는다 |
| 글자 아바타 (`avatarGlyph`) | 무 |
| 그림 아바타 (`avatar`) | 캐릭터 설정화의 임시 얼굴 크롭 (아래 '아바타') |
| 화면 소개 (`intro`) | 예의 바르게 핵심을 짚고, 끝까지 설명하는 젊은 무당. |
| 대표 대사 (`signatureLine`) | 듣기 좋은 말만 원하시면 다른 곳이 더 편하실 거예요. 여기서는 근거와 조건부터 말씀드리고, 약점도 숨기지 않습니다. 대신 어떻게 다룰지까지 끝까지 설명해 드리죠. |

`intro`, `signatureLine`, `lines`는 화면과 모델 없는 안내에만 쓰고 생성 지시에 넣지 않는다 (`characterBlock`이 옮기지 않는다, `tests/unit/mujin-persona.test.ts`에서 확인).

## 모델 없이 보내는 문장 (`lines`)

### 기존 열 칸

모두 존댓말이고, 생성 지시에는 들어가지 않는다. 차감 안내의 사실은 묘묘 문장과 뜻이 같다.

| 칸 | 쓰는 때 | 무진 문장의 뜻 |
| --- | --- | --- |
| `outOfScope(topics)` | 후속 질문이 상품 범위 밖일 때 | 범위 밖이라 답할 수 없음, `scope.topicsLabel`까지 볼 수 있음, 그 안에서 다시 물어 달라, 횟수에서 빼지 않음 |
| `partialScope(excluded)` | 일부 질문을 빼고 답했을 때 덧붙임 | 그 이야기는 범위 밖이라 빼고 답함 |
| `notCharged` | 모델이 되물었을 때 덧붙임 | 횟수에서 빼지 않음 |
| `clarify` | 질문이 모호해 되물을 때 | 조금 더 구체적으로, 질문 예 하나, 횟수에서 빼지 않음 |
| `previewDayMaster`, `previewLead`, `previewNone` | 메신저 맛보기(`buildReadingPreview`) | 족자 상품의 무료 부분은 모델이 쓰므로 지금 무진 화면은 이 칸을 쓰지 않는다. 타입이 요구해 존댓말로 채워 두었다. `previewLead`는 규칙의 존댓말 문장을 바꾸지 않고 잇는다 |
| `reaction(kind, seed)` | 질문 없이 칭찬·허세 지적·의심만 보냈을 때 | 칭찬은 태연하게 받고 작은 자기과시, 허세 지적은 여유 있게 받되 근거로 말했다고 함, 의심은 어디가 걸리는지 묻고 근거를 다시 확인하겠다고 함. 같은 말에는 같은 문장(`pick`) |
| `reactionFree` | 반응만 보낸 메시지를 무료로 받을 때 | 이번에는 횟수에서 빼지 않음, 다음부터는 질문 1회로 셈 |
| `reactionCharged` | 무료 횟수를 넘겼을 때 | 한 번만 빼 준다고 했음, 이번에는 질문 1회로 셈 |

### 대화형 입력과 족자 생성 상태 (`lines.intake`)

`PersonaLines`의 선택 칸 `intake?: PersonaIntakeLines`다 (무진 1.0.0부터, 묘묘에는 없다). 화면이 모델 없이 그대로 보여 준다.

- 함수 없이 문자열만 있어 서버 컴포넌트에서 브라우저 컴포넌트로 그대로 넘길 수 있다 (`persona.lines.intake`). `lines`의 다른 칸에는 함수가 있으므로 `lines` 전체를 넘기지 않는다.
- `{name}` 자리는 화면이 별명 호칭으로 바꾼다. 바꿀 값은 `addressFor(persona, 별명).call`(예: 달빛 님)이다. 지금은 `askGender`, `askNow`, `paidDone`에만 있다. 별명을 묻는 `greet`에는 없고 '손님'이라고 부른다.
- 생성 지시에 넣지 않는다 (명세 04 7절: 고정 안내 문장을 본문 생성의 예문으로 쓰지 않는다).

| 칸 | 쓰는 때 | 문장이 지키는 사실 |
| --- | --- | --- |
| `greet` | 첫 인사와 별명 묻기 | 본명이 아니어도 됨 |
| `askGender` | 성별 | 대운의 방향처럼 전통 계산에서 남녀를 나눠 보는 부분이 있어 묻는다 (엔진의 대운 방향 입력, 규칙의 배우자·자녀 십성 대응) |
| `askBirthDate` | 생년월일 6자리와 양력·음력·윤달 | 입력 예는 기존 입력 화면의 예(980919)와 같다 |
| `askPlace` | 출생지역 | 같은 이름은 행정구역으로 구분, 시진의 실제 시각이 지역에 따라 달라 시간보다 먼저 묻는다 (00_START_HERE.md 결정 8) |
| `askTime` | 시진과 '시간 모름' | 모르면 임의 시각으로 채우지 않고 시주 없이 읽을 수 있는 데까지만 읽는다 |
| `askNow` | 지금의 나 (선택) | 고른 항목만으로 사정을 짐작하지 않음, 사주 판단은 바뀌지 않음, 건너뛰어도 빠지는 장이 없음 (명세 03 2~5절) |
| `askConcern` | 진짜 궁금한 점 (선택) | 여러 개여도 됨, 관련 장과 마지막 정리에서 짚음, 비워도 됨 |
| `review` | 입력 확인과 수정 | 생년월일이나 시간이 다르면 원국이 달라진다 |
| `computing` | 원국 계산과 자료를 살피는 중 | 걸리는 시간이나 진행률을 말하지 않는다. 원국 계산이 이미 끝난 생성 초기에 보여도 틀리지 않게 '자료를 살피는 중'까지 말한다 (명세 05 2절) |
| `writingFree` | 무료 부분 작성 중 | 기초 분석과 첫 장을 쓰는 중 (건조한 한마디) |
| `freeDone` | 무료 부분 완료, 유료 장 안내 직전 | 첫 장은 그것만으로 끝까지 읽히게 썼다 (명세 01 2절: 무료 성향 분석은 완결) |
| `writingPaid` | 유료 장 작성 중 | 다 쓴 장부터 제자리(목차 순서)에 펼친다 |
| `paidDone` | 전체 완료 | 배경의 식은 차가 한 번 나온다 |
| `sectionFailed` | 한 장 작성 실패 | 다시 시도하면 그 장만 다시 쓰고 이미 쓴 장은 그대로 |
| `locked` | 잠긴 유료 범위 | 구매하거나 이용권을 사용한 뒤에 쓴다, 미리 써 두고 가린 것이 아니다 (명세 05 4절). 개인 내용이 없다 |

## 버전

| 버전 | 함께 쓰는 지시 | 바뀐 점 |
| --- | --- | --- |
| 1.0.0 (현재) | 무진 작성 지시 (Pass 1 초안, Pass 2 무진 문장, 후속 질문). 지시 버전 이름은 `mujin-prompts.ts` 작업이 정한다 | 첫 설정 |

- 설정을 바꿀 때는 이 설정을 고치지 않고 새 버전을 더한다. 지금의 `MUJIN`을 `MUJIN_1_0_0` 같은 이름으로 남겨 `EARLIER_PERSONAS`에 넣고 새 `MUJIN`을 만든다. 생성 작업은 시작할 때 고정한 지시 버전에 맞는 설정을 쓴다 (`findPersona(id, version)`). 그래서 이어 쓰는 작업에 새 설정이 섞이지 않는다.
- 한 번 쓴 번호는 되돌린 작업의 것이라도 다시 쓰지 않는다 (묘묘 2.0.0과 같은 원칙).
- 지금 `personaVersionFor`(`prompts.ts`)는 묘묘 기준 표이고, 표에 없는 지시 버전에는 "1.0.0"을 돌려준다. 무진 1.0.0과 우연히 같을 뿐이다. 무진 지시 버전은 표(또는 캐릭터별 표)에 명시해 등록해야 한다. 등록하지 않은 채 무진 1.1.0을 더하면 새 지시로 시작한 작업도 1.0.0 설정을 쓰게 된다.
- 그림·이름 같은 화면 값(`MUJIN_FACE`)은 생성 지시에 들어가지 않으므로, 아바타 그림만 바꿀 때는 설정 버전을 올리지 않는다 (묘묘의 `MYOMYO_FACE`와 같다).
- 풀이 기록: `readings.persona_id`·`persona_version`, 무진 작성 계획의 `MujinPlan.personaId`·`personaVersion`.

## 아바타 (임시 리소스)

B05 프로필·상반신 그림을 받기 전까지 쓰는 임시 크롭이다. 최종 아트가 아니다.

| 항목 | 값 |
| --- | --- |
| 원본 | A01 캐릭터 설정화 `public/images/personas/mujin-character-sheet.png` (PNG 1536×1024, 배경과 라벨 글자가 있음, 투명 아님) |
| 쓰는 칸 | 왼쪽 위 얼굴 클로즈업 칸 (원본 약 가로 0~344px, 세로 0~420px) |
| 크롭 | `square: { x: 0.073, y: 0.027, size: 0.15 }` = 원본 약 (112, 28)에서 한 변 230px. 얼굴 칸 안이라 옆 칸의 그림과 글자가 끼지 않는다 |
| alt | 빈 문자열 (바로 옆에 이름이 있는 장식) |
| 표시 크기 | `PersonaAvatar` 40px(작게), 56px(크게). 크롭 영역 230px이라 56px 원을 3배 화면(168px)에서도 채운다 |

확인 방법: `SquareArt`(`src/components/ui/art.tsx`)와 같은 계산으로 220px 정사각(가운데 십자선)과 96·56·40px 원을 그린 HTML을 Playwright로 찍어 눈으로 보고, 얼굴이 정사각 가운데에 오도록 후보 여덟 개 가운데서 골랐다 (확인용 파일은 저장소 밖에 두었다). 40·56px 원에서 눈·코·입이 보인다. 얼굴이 오른쪽 위를 올려다보는 3/4 구도라 이목구비는 가운데보다 약간 오른쪽에 있고, 아래쪽 가장자리에 턱을 괸 손가락 끝이 조금 보인다. 설정화 아래 '표정 예시' 줄의 정면 얼굴은 칸이 작고(약 130px) 바로 아래에 라벨 글자가 있어 쓰지 않았다.

B05 요청 규격(00_START_HERE.md 9절: 얼굴 정면, 정사각 512px 이상, 투명 배경 권장)에는 못 미친다. B05를 받으면 파일을 `public/images/personas/`에 두고 `MUJIN_FACE.avatar`의 `src`·`width`·`height`·`square`를 바꾼 뒤, `tests/unit/mujin-persona.test.ts`의 크롭 위치 확인을 함께 고친다.
