### 장애 기록 (2026-11-10)

로컬 앱을 실제 Supabase에 연결해 궁금한 점이 있는 풀이를 결제했을 때 생성이 4번 모두 `internal`로 실패했다.

- 원인: `20261110120000_reading_quality.sql`이 실제 데이터베이스에 적용되지 않아 `reading_analyses` 테이블이 없었다. 생성 첫 단계의 분석 저장소 조회가 매번 예외를 냈고, OpenAI는 한 번도 호출되지 않았다(`llm_calls = 0`). 시도 상한(4회)에 걸려 화면에서도 다시 시도할 수 없게 됐다.
- 조치: migration을 적용하고, 해당 풀이 한 건의 작업을 `queued`·시도 0회로 되돌렸다(프롬프트·모델 버전은 처음 값 유지). 결제와 질문 횟수는 건드리지 않았다.
- 재발 방지: 분석 저장소는 보조 기능이므로 조회·저장이 실패하면 경고 로그만 남기고 저장 없이 생성을 계속한다. 내부 실패 로그에 원인 코드(`analysis_load_failed` 등 앱의 고정 코드)를 남긴다. 테스트: `tests/unit/pipeline.test.ts`의 "분석 저장소 장애".
- 배포 순서: 새 migration은 앱 배포 전에 적용한다 (README).

### OpenAI 요청 수 확인 (2026-11-10)

대시보드에 134회가 찍혔지만 앱이 보낸 요청은 4회였다.

| 흐름 | 앱이 보낸 요청 |
| --- | --- |
| 생성 실패 4번 (migration 미적용) | 0회. 분석 저장소 조회에서 멈춰 OpenAI까지 가지 않았다 |
| 복구 후 최초 풀이 | 2회 (질문 정리 1 + 풀이 1), 로그 `[generation] done { calls: 2 }` |
| 후속 질문 1개 | 2회 (질문 정리 1 + 답변 1), 로그 `[followup] done { calls: 2 }` |

나머지 약 130회는 같은 키로 실행한 개발 확인 스크립트(`npm run llm:compare`, 가상 사례)였다. 평소 풀이 1건은 궁금한 점이 있으면 2회, 없으면 1회이고, 검사에 걸리면 1회가 더 붙는다. 후속 질문은 2회(범위 밖이면 1회)다.

### 로그인 없이 둘러보기와 첫 화면 그림 (2026-11-11)

- 스플래시(`/`)의 시작하기는 로그인 없이 홈으로 간다. 홈, 탐색, 상품 상세는 로그인 없이 볼 수 있다.
- 보관함, 마이, 사주 입력(상품 상세의 "내 사주 입력하기"), 맛보기, 결제, 풀이 화면은 로그인이 필요하다. 로그인하지 않았으면 `src/proxy.ts`가 로그인 화면으로 보내고(`next`에 누르려던 주소), 로그인하면 그 화면으로 돌아온다.
- 홈과 탐색에서 첫 화면에 보이는 포스터(앞의 4개)는 바로 불러오고 첫 번째는 가장 먼저 받는다 (`loading="eager"`, `fetchPriority="high"`). Next 개발 서버의 LCP 경고를 없앴다.
- 상품 상세와 보관함은 불러오는 동안 실제 화면과 같은 모양의 스켈레톤을 보여 준다 (`src/components/ui/skeleton.tsx`). 디자인 시스템이 무한 반복 효과를 금지하므로 움직이지 않는다.

## 이어서 할 작업

1. `.env.local`에 Supabase 키, OpenAI 키, 토스 테스트 키를 넣는다.
2. Supabase Redirect URL에 `http://localhost:3000/auth/callback`을 추가한다.
3. 실제 카카오·구글 로그인과 이메일 없는 카카오 계정을 확인한다.
4. 토스 테스트 결제로 전체 흐름을 확인한다.
5. `npm run llm:check`로 권한을 확인하고 실제 풀이 품질을 읽어 보며 프롬프트를 조정한다.
6. `npm run llm:compare`로 gpt-6-luna를 비교한다. 절차는 `docs/LLM_OPERATIONS.md`에 있다.

## 공개 전 필요한 일

- 이용약관, 개인정보 처리방침 작성과 화면 연결. 출생정보와 입력 내용이 OpenAI로 전달되는 범위도 고지한다.
- 토스 실제 키 전환 (`PAYMENTS_ALLOW_LIVE=true`)과 환불·문의 절차
- 명리 전문가의 규칙 검토. 현재 규칙은 모두 `unreviewed`다.
- 호스팅의 요청 시간 제한 확인. 풀이 생성이 요청 안에서 끝나야 하며 `maxDuration`은 300초로 설정했다.
- 새 상품을 만들 때의 포스터·배너 그림 (첫 상품은 묘묘 그림을 쓴다)

## 엔진 관찰 사항

엔진 소스는 수정하지 않았다. `sajuengine 0.1.0`에서 윤달이 없는 해의 윤달 입력을 넣어도 `session.execute`가 예외를 던지지 않았다. 앱은 공개 변환기로 먼저 검증하므로 영향이 없지만, 엔진을 직접 호출할 때는 주의가 필요하다.
