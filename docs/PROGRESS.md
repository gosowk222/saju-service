# 진행 상황 (first-product-mvp)

브랜치: `feat/first-product-mvp`. 기록일: 2026-11-09.

## 결정 사항

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 결제 제공자 | 토스페이먼츠 v2 결제 위젯 | 기존 제공자가 없었음. 원화 결제와 테스트 환경이 갖춰져 있음 |
| 데이터 쓰기 | 서버 전용 Postgres 함수 | 결제 확정과 질문 차감을 한 트랜잭션으로 처리하고 브라우저 쓰기를 차단 |
| 생성 실행 | 요청 안에서 끝내고 점유 시간으로 복구 | 서버 응답 뒤 작업이 계속된다고 가정하지 않음 |
| 앱 규칙 | 십성 분포 기반 2개, 미검토 표시 | 엔진 기본 결론이 대부분 보류 상태라 채택할 해석이 필요 |
| 지역 자료 | 앱에 포함한 JSON (2,762건) | 요청마다 GeoNames에 접속하지 않음 |
| 모의 기능 | 앱 코드에 넣지 않고 `tests/`의 가짜 서버로 대체 | 모의 로그인이나 결제가 운영에 노출될 경로를 없앰 |
| Next.js `runtime` 설정 | 사용하지 않음 | Cache Components가 지원하지 않으며 기본이 Node.js |
| `package.json`의 `type: module` | 추가 | 엔진이 ESM 전용이라 검증 스크립트가 불러오려면 필요 |
| `next.config.ts`의 추적 경로 | `/*`, `dist/**/*`로 수정 | 안내서 기준 값. 기존 값으로는 배포 시 계산 파일이 빠질 수 있음 |

브라우저 테스트의 로그인, 결제, 답변은 모두 가짜 서버의 고정 값이다. 동시 요청은 테스트용 Postgres의 연결이 하나라 순차 중복 호출로 확인했다. 실제 병렬 처리는 데이터베이스의 행 잠금과 고유 인덱스에 의존한다.

## 이어서 할 작업

1. `.env.local`에 Supabase 키, OpenAI 키, 토스 테스트 키를 넣는다.
2. Supabase Redirect URL에 `http://localhost:3000/auth/callback`을 추가한다.
3. 실제 카카오·구글 로그인과 이메일 없는 카카오 계정을 확인한다.
4. 토스 테스트 결제로 전체 흐름을 확인한다.
5. `npm run llm:check`로 권한을 확인하고 실제 풀이 품질을 읽어 보며 프롬프트를 조정한다.
6. `npm run llm:compare`로 gpt-6-luna를 비교한다. 절차는 `docs/LLM_OPERATIONS.md`에 있다.

## 공개 전 필요한 일

- 이용약관, 개인정보 처리방침 작성과 화면 연결. 출생정보와 입력 내용이 OpenAI로 전달되는 범위도 고지한다.
- 토스 실제 키 전환 (`PAYMENTS_ALLOW_LIVE=true`)과 환불·문의 절차
- 명리 전문가의 규칙 검토. 현재 규칙은 모두 `unreviewed`다.
- 호스팅의 요청 시간 제한 확인. 풀이 생성이 요청 안에서 끝나야 하며 `maxDuration`은 300초로 설정했다.
- 포스터 일러스트 자산

## 엔진 관찰 사항

엔진 소스는 수정하지 않았다. `sajuengine 0.1.0`에서 윤달이 없는 해의 윤달 입력을 넣어도 `session.execute`가 예외를 던지지 않았다. 앱은 공개 변환기로 먼저 검증하므로 영향이 없지만, 엔진을 직접 호출할 때는 주의가 필요하다.
